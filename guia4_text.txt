INTRODUCCIÓN  
 
Una tienda registra ventas procedentes de diferentes ciudades. Cada venta contiene un 
producto, una cantidad y un precio; posteriormente también incluirá una fecha. El problema 
consiste en almacenar esos registros y determinar cuántas ventas, unidades e ingresos 
corresponden a cada ciudad. Primero se trabaja con cuatro documentos para comprobar cada 
operación; luego se a0mplía a 100 000 registros. 
MongoDB es un sistema de bases de datos. Python es un lenguaje de programación que puede 
comunicarse con ese sistema. Los programas de esta guía utilizan PyMongo, el controlador 
oficial de Python. Compass permite observar los mismos datos desde una interfaz gráfica. 
Los datos permanecen en MongoDB aunque se cierre Python o Compass, siempre que se 
conserve el almacenamiento del servidor. 
 
 
VII  
 
MARCO TEÓRICO  
1 BASES DE DATOS NO RELACIONALES 
NoSQL reúne modelos de almacenamiento distintos al modelo relacional tradicional. 
MongoDB y CouchDB se orientan a documentos; Cassandra utiliza columnas anchas; Neo4j 
trabaja con grafos; Redis proporciona estructuras de datos en memoria. NoSQL no significa 
ausencia de reglas ni superioridad automática sobre SQL. El modelo debe responder a las 
consultas y restricciones del caso. 
2 DOCUMENTOS Y COLECCIONES 
Un documento contiene campos y valores. MongoDB lo almacena en BSON, una 
representación binaria que admite tipos como fechas, números, listas y documentos anidados. 
En la consola se utiliza una sintaxis parecida a JSON. Una colección reúne documentos y una

4 OPERACIONES CRUD 
Create inserta documentos; Read consulta; Update modifica; Delete elimina. Una consulta 
utiliza un filtro, equivalente a una condición. La proyección selecciona los campos que se 
muestran. Los campos _id explícitos permiten repetir inserciones mediante upsert sin duplicar 
registros. 
5 AGREGACIÓN Y RELACIÓN CON MAPREDUCE 
Un pipeline de agregación transforma datos mediante etapas. $match filtra; $group agrupa y 
calcula; $sort ordena; $project selecciona o transforma campos. $sum suma y $multiply 
multiplica. Agrupar por ciudad y sumar importes cumple una finalidad parecida al ejercicio 
de agrupación por clave de MapReduce, pero el pipeline es una API diferente y no prueba 
que se esté ejecutando un trabajo Hadoop. 
6 ÍNDICES Y ESCALABILIDAD 
Un índice organiza valores de ciertos campos para facilitar búsquedas. Consume 
almacenamiento y añade trabajo a las escrituras. Su utilidad depende del filtro y de cuántos 
documentos se necesitan devolver. explain permite observar documentos y entradas de índice 
examinados. La replicación mantiene copias y facilita disponibilidad; el sharding reparte 
datos entre shards y permite escalar horizontalmente. No son la misma operación. 
Esta guía usa un solo servidor. Cien mil registros permiten observar técnicas relacionadas con 
Big Data, pero no existe un número universal que convierta un conjunto en Big Data. El

from pymongo import MongoClient 
from pymongo.errors import PyMongoError 
cliente = MongoClient( 
    "mongodb://localhost:27017/", 
    serverSelectionTimeoutMS=5000 
) 
try: 
    cliente.admin.command("ping") 
    print("Conexión correcta") 
    ventas = cliente["guia5_bigdata"]["ventas_demo"] 
    print("Total:", ventas.count_documents({})) 
    filtro = {"ciudad": "Arequipa"} 
    for venta in ventas.find(filtro, {"_id": 0}):

except PyMongoError as error: 
    print("Error de MongoDB:", error) 
    raise 
finally: 
    cliente.close()

from pymongo import MongoClient 
COLECCION = "ventas_masivas" 
cliente = MongoClient( 
    "mongodb://localhost:27017/", 
    serverSelectionTimeoutMS=5000 
) 
try: 
    cliente.admin.command("ping") 
    ventas = cliente["guia5_bigdata"][COLECCION] 
    if ventas.count_documents({}) == 0: 
        raise RuntimeError("Primero ejecute el generador") 
    etapas = [ 
        {"$group": { 
            "_id": "$ciudad", 
            "ventas": {"$sum": 1}, 
            "unidades": {"$sum": "$cantidad"}, 
            "ingresos": {"$sum": { 
                "$multiply": ["$cantidad", "$precio"] 
            }} 
        }}, 
        {"$sort": {"ingresos": -1, "_id": 1}} 
    ] 
    resultados = list(ventas.aggregate(etapas)) 
    for fila in resultados: 
        print(fila) 
    independiente = defaultdict( 
        lambda: {"ventas": 0, "unidades": 0, "ingresos": 0} 
    ) 
    proyeccion = { 
        "_id": 0, "ciudad": 1, "cantidad": 1, "precio": 1 
    } 
    for venta in ventas.find({}, proyeccion).batch_size(1000): 
        fila = independiente[venta["ciudad"]] 
        fila["ventas"] += 1 
        fila["unidades"] += venta["cantidad"] 
        fila["ingresos"] += venta["cantidad"] * venta["precio"] 
    obtenido = { 
        fila["_id"]: { 
            "ventas": fila["ventas"], 
            "unidades": fila["unidades"], 
            "ingresos": fila["ingresos"] 
        } 
        for fila in resultados 
    } 
    if obtenido != dict(independiente): 
        raise RuntimeError("No coinciden los dos cálculos") 
    print("Validación correcta por ciudad") 
    print("Total ventas:", sum(x["ventas"] for x in resultados)) 
    print("Total unidades:", sum(x["unidades"] for x in resultados)) 
    print("Total ingresos:", sum(x["ingresos"] for x in resultados))
